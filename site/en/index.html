MCP server for Grist

An AI assistant that works in your Grist documents

mcp-server-grist connects an AI assistant (Claude, or any MCP-compatible client) to the Grist API. Ask it in plain language to find information, fill in a table or create a complete database with its relations: it does so in your documents, with your permissions.

Set up in one minute

You need a Grist API key (in Grist: Profile settings → API) and the API address of your instance. uvx runs the server, no installation needed.

Claude Desktop

Add this to claude_desktop_config.json, then restart Claude.

{
  "mcpServers": {
    "grist": {
      "command": "uvx",
      "args": ["mcp-server-grist"],
      "env": {
        "GRIST_API_KEY": "your_api_key",
        "GRIST_API_URL": "https://docs.getgrist.com/api"
      }
    }
  }
}

Claude Code

One command in the terminal.

claude mcp add grist \
  -e GRIST_API_KEY=your_api_key \
  -e GRIST_API_URL=https://docs.getgrist.com/api \
  -- uvx mcp-server-grist

Other MCP clients

Command uvx, argument mcp-server-grist, and the two variables GRIST_API_KEY and GRIST_API_URL. The server also speaks HTTP (option --transport streamable-http).

uvx mcp-server-grist

Docker

For an isolated deployment.

docker run -i --rm \
  -e GRIST_API_KEY=your_api_key \
  -e GRIST_API_URL=https://docs.getgrist.com/api \
  mcp/grist-mcp-server

Before connecting your data

  • The assistant acts with your API key: it can do anything you can do in Grist, including deleting. Use a key from an account with suitable permissions.
  • SQL queries are read-only.
  • In HTTP mode, the server does not authenticate its clients: keep it on 127.0.0.1 or behind an authenticated proxy.
  • Re-running a schema creation creates nothing twice: existing tables are left untouched.
